# 简谱（Jianpu）Web 编辑器 —— 设计文档（完整版）

> 目标：一个纯前端、可离线使用的简谱编辑网页。用户输入数字简谱，实时渲染成规范的简谱排版，
> 支持播放（Web Audio 合成 + 逐音高亮），并可导出 **JSON / MIDI / SVG / 图片(PNG) / 文本简谱**
> 五种格式（打印走浏览器）。**MusicXML 未实现**：与打谱软件交换走 MIDI，工程文件用 JSON。
> 本文件为当前项目的权威设计文档：`docs/DESIGN.md`（随代码同步更新）。

---

## 1. 目标与范围

### 1.1 核心目标
- 在浏览器中**编辑**简谱：增删改音符、时值、附点、小节、歌词、调号、拍号、速度。
- **实时渲染**为符合简谱记谱规范的版面（下划线、增时线、高音点、小节线、连音线等）。
- **播放**：用 Web Audio 合成简单的 MIDI 风格音频，支持逐音高亮跟随。
- **导出**：JSON（工程文件）、MIDI(.mid)、SVG、PNG 图片、文本简谱；打印走浏览器。
- 纯前端，无后端；工程文件可存浏览器本地(localStorage)或下载为 .json。

### 1.2 非目标（当前版本不做）
- 多人协作、云端账号、服务端渲染。
- 复杂钢琴多声部总谱（v1 聚焦单旋律 + 歌词；多声部列为后续）。
- 制谱级精细排版（Optical spacing、beam 跨行连接等，列为后续）。

## 2. 简谱记谱规范（渲染必须满足）

### 2.1 音高
- 基本音级用数字 `1 2 3 4 5 6 7`（do re mi fa sol la si），`0` 表示**休止符**。
- **调号**：`1=C`、`1=G`、`1=bB` 等，表示首调唱名对应的绝对音高。
- **八度点**：
  - 数字**上方**加 `·` = 高八度（每加一个点 = 高一个八度，可叠加）。
  - 数字**下方**加 `·` = 低八度（可叠加）。
  - 渲染时点要精确对齐到数字正上方/正下方，多个点垂直等距排列。
- **升降号**：`#5`、`b7` 写在数字**左前方**，字号略小。

### 2.2 时值（以四分音符为基准）
| 名称 | 简谱写法 | 相对时值 |
|---|---|---|
| 全音符 | `1 - - -` | 4 拍 |
| 二分音符 | `1 -` | 2 拍 |
| 四分音符 | `1` | 1 拍 |
| 八分音符 | `1`（数字下方一条横线） | 1/2 拍 |
| 十六分音符 | `1`（数字下方两条横线） | 1/4 拍 |
| 三十二分音符 | `1`（数字下方三条横线） | 1/8 拍 |
| 附点四分 | `1.`（附点） | 1.5 拍 |
| 附点二分 | `1 - -`（满两拍时附点由增时线表达，不写附点） | 3 拍 |

- **减时线**：八分/十六分/三十二分，在数字**正下方**画 1/2/3 条短横线，与相邻同类音符的横线**连成连续线**（beam 效果）。
- **增时线**：`-` 写在数字右侧，与数字**水平居中对齐**（垂直居中于数字中线）。
- **附点**：写在数字右侧的点（·）
- 休止符：`0`；二分休止符写作两个 `0`、全休止符写作四个 `0`，每个「0」与同小节四分休止符 / 四分音符落在同一拍份位置
- **小节线**：单线 `|`，终止线双线 `||`，反复记号 `|: :|`。

### 2.3 连音与分句
- **连音线（tie，同音相连）**：只在**同音高**音符之间合并时值，写在音符上方，播放时只发一次；
  跨小节的长音保留成跨小节连音线。
- **圆滑线（slur）**：独立的分句弧线，与连音线互不改写；连续标记三个以上音符共用一条弧线，跨行按行分段续接。

### 2.4 版面
- 页眉（歌曲信息）画在谱面 SVG 里，编辑器 / 导出 SVG / PNG / 打印同一份版式，自上而下三行：
  **标题独占一行**（居中，大字 + 宽字距），其下居中排副标题与「演唱 ×××」。
- 居中栏之下空出一段间距排「信息带」：调号(`1=C`)、拍号(`4/4`)、速度(`♩=120`) 左对齐到谱面左边距；
  「×× 作词 / ×× 作曲」右对齐到右边距，两栏同一水平带 —— 这些小字不与标题、演唱同线。
  极窄页下右栏撞到左栏时整栏下移，绝不重叠
  （纯计算见 `core/layout.ts` 的 `layoutHeader`，估宽见 `core/metrics.ts` 的 `textWidth`）。
- 歌词：每个音符正下方对齐一个音节；字与音符**居中对齐**，**同一行所有音节对到一条基线**
  （基线让开「下划线 + 低音八度点」的堆叠）；多音节词的连字符由歌词自带，排版不添加。
- 每行若干小节，自动换行（每行尽可能多的小节，`meta.barsPerLine` 可固定）；行间距固定。
- 小节内记号按**拍份列宽**分配水平宽度（非等宽）：全曲所有小节共用同一套列宽，
  节拍网格在整页处处对齐，节奏视觉比例正确（见 §6.1）。

## 4. 数据模型（核心，决定一切导出质量）

```ts
// core/model.ts（节选）
export type Accidental = 'natural' | 'sharp' | 'flat';
/** 时值用分母表示：1=全音符 2=二分 4=四分 8=八分 16=十六分 32=三十二分 */
export type Duration = 1 | 2 | 4 | 8 | 16 | 32;
export type Degree = 1 | 2 | 3 | 4 | 5 | 6 | 7;

export interface NoteEvent {
  kind: 'note'; id: string;
  degree: Degree;
  octave: number;                 // 相对调主的八度点，钳制在 -2..2
  accidental: Accidental;
  duration: Duration; dotted: boolean;
  tie: boolean;                   // 与前一个同音音符连成一条时值
  slur: boolean;                  // 与前一个音符之间画圆滑线
  triplet: boolean;               // 三连音成员（渲染为数字上方的 3）
  lyric: string;                  // 歌词音节（一个汉字 / 一个英文音节）
  velocity: number;               // 来自 MIDI 导入，只影响播放音量，不是可编辑记号
}
export interface RestEvent { kind: 'rest'; id: string; duration: Duration; dotted: boolean }
export interface DashEvent { kind: 'dash'; id: string }  // 增时线，时值继承前面那个音符
export type ScoreEvent = NoteEvent | RestEvent | DashEvent;

export type BarlineKind = 'none' | 'normal' | 'repeat-start' | 'repeat-end' | 'final';
export interface Bar { id: string; events: ScoreEvent[]; left: BarlineKind; right: BarlineKind }

export interface Score { meta: Meta; bars: Bar[] }
// meta: title / subtitle / singer / composer / lyricist / tonic / timeSig / tempo
//       / showLyrics / showBarNumbers / barsPerLine / fontSize / instrument / loop …
```

**为什么这样建模**：
- **单声部**：没有 `part` / `staff` 维度，`Score.bars` 直接就是事件序列（多声部不在当前范围）。
- 时值用**分母**（`4` = 四分音符）而不是字符串，拍数换算集中在 `model.ts` 的
  `durationBeats`（`4 / 时值`）/ `noteBeats`（含附点）/ `barBeatLength` / `measureBeats`，不散落各处。
- 与 MIDI 的「音高 + 时值 + 速度」一一对应 → MIDI 导入 / 导出干净。
- 与文本简谱可双向映射 → 文本导入 / 导出干净。
- 与 SVG 排版所需字段（时值→宽度、附点→点、八度→点、歌词→下对齐）一一对应。
- 事件 `id` 由 `nextId()` 生成且全曲唯一：排版、渲染、播放高亮、拖拽都靠它定位记号。

### 4.1 音高 → MIDI 音号
```
midi = tonicMidiBase(tonic) + 12*octave + DEGREE_PC[degree] + accidentalOffset(accidental)
DEGREE_PC = {1:0, 2:2, 3:4, 4:5, 5:7, 6:9, 7:11}
accidentalOffset = {sharp:+1, flat:-1, natural:0}
```
> 首调关键：`1=C` 时 `1`=C4(60)；`1=G` 时 `1`=G4(67)；`1=bB` 时 `1`=Bb4(70)。
> **`tonicMidiBase` 恒把调主落在 C4–B4 窗口**（`tonicMidiBase(tonic, 4)`）：`Tonic` 只有音名、
> 没有八度字段，所以导入、播放、MIDI 导出、移调 notes 模式**必须用同一个基准**，
> 否则谱面自己看着自洽，播出来 / 导出去却整首差一个八度（见 `tests/midi-octave.test.ts`）。

### 4.2 时值 → tick
```
ppq = 480 (ticks per quarter)
ticks = { 1:1920, 2:960, 4:480, 8:240, 16:120, 32:60 }   // 时值即分母，全部整除无误差
附点 ×1.5（模型只有 dotted: boolean，不支持双附点）
```

## 5. 技术选型（纯前端）

| 关注点 | 选型 | 理由 |
|---|---|---|
| 渲染 | **SVG**（自绘） | 矢量清晰、易导出 PNG、易做点击选区与高亮；不依赖制谱库 |
| 布局 | 自研排版引擎 | 简谱排版无成熟轻量库；自研可控且满足规范 |
| 音频 | **Web Audio API** 自合成（振荡器+包络） | 零依赖、离线可用、低延迟；用 `AudioContext` 调度 |
| MIDI 导出 | 自写 SMF 写入器（format 1） | 不依赖外部库，可控 |
| MusicXML | **未实现** | 与打谱软件交换走 MIDI；工程文件用 JSON |
| 图片导出 | SVG→`<canvas>`→`toDataURL('image/png')` | 标准做法 |
| 文本导出 | 自写序列化 | 见 §8 |
| 构建 | Vite + TypeScript | 类型安全、热更新 |
| 状态 | 单向数据流 + 命令模式(撤销) | 简单可靠 |

> 关键原则：**不引入制谱引擎**（如 OpenSheetMusicDisplay/Verovio），它们面向五线谱且体积大；简谱自研更可控。

## 6. 核心算法

### 6.1 排版引擎（core/layout.ts + core/metrics.ts）
输入：`Score` + 容器宽度。输出：`LayoutResult`（**纯计算、不碰 DOM**，可在 node 环境直接单测）。

**节拍网格列宽（全曲统一）**：小节按拍号切成「拍份」（四分音符 = 1 拍份，八分 = 0.5，三十二分 = 0.125），
每列宽度由两类约束取 max，并且**全曲所有小节共用同一套列宽** → 节拍网格在整页处处对齐：
1. **严格盒**（必须撑满自己那格，列宽按「自然宽度 / 它占的拍份数」摊算）：小节末记号
   （盒要铺到小节右内边距，跨小节的相邻记号才不撞）、增时线记号与带增时线的长音
   （每根横线至少占一个拍份单位）、拆成若干「0」的二分 / 全休止符（逐拍落位）。
2. **墨迹相撞**（其余记号只要求相邻墨迹不撞）：中心距 ≥ 左记号右半墨迹 + 右记号左半墨迹，
   除以时值占比 Δ 换成列宽下限。升降号墨迹在数字**左侧**，必须计入**右邻**的左半宽。
   带歌词的记号**不算**严格盒：音节居中落在数字中心下方，中心距由墨迹约束给出。

列宽取全曲各列 max 后按容器宽度**只放大不缩小**：`fitPerLine` 用自然宽度决定每行小节数
（`meta.barsPerLine` 可手动指定），缩放系数只作用于 `barWidth` 并记进 `LayoutResult.scale`，
`slotPosition` 与休止符 / 增时线落位一律用**未缩放**列宽。

**垂直布局（行与行）**：
- 行高由每行最深的记号撑出来：上方 = 连音线 / 圆滑线 / 三连音标记 + 高音八度点，
  下方 = 减时线 + 低音八度点 + 歌词带。
- 歌词：每个音符下方居中一个音节，**同一行所有音节对到一条基线**（基线让开「下划线 + 低音八度点」
  的堆叠），字号 `LYRIC_FONT_SIZE` = 数字的 0.6 倍。
- 页眉（标题 / 副标题 / 演唱 / 调号速度 / 词曲作者）是**谱面 SVG 的一部分**（`layoutHeader`），
  第一行谱表从 `header.height` 起排 → 编辑器、导出 SVG / PNG、打印四处版式一致。
- 小节线只覆盖**音符区**，不伸进歌词带（竖线穿过汉字会读成表格线）；同一行所有小节线等长。
- 减时线按拍分组：横线连到同组相邻记号，小节末断开（符合规范）。

**输出结构**（节选，见 `core/layout.ts`）：
```ts
type NoteBlock = { eventId; barIndex; eventIndex; kind: 'note'|'rest'|'dash';
                   x; width; cx; dashes; dashSlots?; restSlots?; beatIndex;
                   degree; octave; accidental; duration; dotted; triplet; lyric;
                   lyricOffset; underlines; dotsAbove; dotsBelow; topExtent; bottomExtent };
type BarSlot   = { barIndex; x; width; slotWidths: number[]; slotWidth;
                   leftBarline; rightBarline };
type LayoutResult = { systems: System[]; width; height; scale; header?: LayoutHeader };
```
渲染层（`core/render.ts`）只照坐标落笔，不自己算几何——排版层给出的
`dashSlots` / `restSlots` / `lyricOffset` / 小节线 `top`/`bottom` 就是最终位置。

### 6.2 播放调度（audio/player.ts + ui/transport.ts）
- `buildPlaybackPlan(score)` 把谱面拍数换算成**绝对音高**（首调：`tonicMidiBase(tonic, 4)` +
  `DEGREE_PC[音级]` + 八度点 + 升降号），并给出每个记号的起止拍。**休止符也进计划**
  （`kind:'rest'`、`midi` 是 NaN，不发声音频节点，只供高亮），末尾休止符计入总拍数。
  连音线续接音符（`tied`）与增时线不发声——时值累加进链首，所以长音期间是链首那个音一直亮着。
- **前瞻调度**：`play()` 只锚定时间轴，`pump()` 每 25ms 在 0.5 秒窗口内逐批创建声部
  （一次排完整首会在长谱面上瞬间造出几千个节点，建图尖峰压垮音频线程的渲染预算）；
  后台标签页一次排完剩余整段（rAF 停摆、定时器节流到 1 秒以上）。
- 音色：`OscillatorNode` + 滤波器 + `noteEnvelope()` 五点开包络（起音 → 峰值 → 持续 → 尾音 → 释音）。
  **音长由增益包络决定**，不是由振荡器决定：持续电平必须停在可听区，释音以时值结束点为中心。
- **防爆音**：主输出串一级 WaveShaper 软限幅（不直接进 destination）；停音一律淡出
  （先 `setValueAtTime` 停在当前电平，再线性拉到 0，淡出期间不断开节点）；
  起播点钳到当下，避免「时间早于当前」的自动化事件塌成增益跳变。
- 逐音高亮：到点回调 `onNote` → `scoreView.setPlaying(eventId)`，并滚动跟随光标。
- 控制：播放按钮三态（停止 / 播放 / 暂停，暂停断点**存拍**不存秒，暂停期间移动高亮则断点作废）、
  停止（淡出 + 回到开头）、速度、倍速、循环。

### 6.3 文本简谱 ↔ 模型（core/jianpu-text.ts）
- 解析规则（与 README「简谱文本语法」同一份）：`1-7` 音级、`0` 休止（`00` / `0000` = 二分 / 全休止）、
  `.` 附点、`/` `//` `///` 时值缩短一级、`-` 增时线、`'` `''` 高八度、`,` `,,` 低八度、
  `#` / `b` 数字前缀升降、`|` 小节线、`|:` / `:|` 反复线。
- 整段不写 `|` 时按当前拍号自动切分小节；小节超拍自动补小节线，缺拍补休止符。
- 导出文本：满两拍以上的音写作「数字 + 增时线」，二分 / 全休止写成 `00` / `0000`，
  保证可被自身解析（round-trip）。三连音、圆滑线、歌词**不在**文本格式内。
- 调号 / 拍号 / 速度 / 标题等乐曲信息不在文本里，用侧栏「乐曲信息」改。

## 7. 简谱排版规范（满足项）

### 7.1 音高
- [x] 数字 1–7 与 0（休止）
- [x] 高音点（上）、低音点（下），可叠加（钳制在 ±2 个八度），垂直居中对齐数字
- [x] 升降号 `#` `b` 置于数字左前（模型只有 natural / sharp / flat，**不支持重升 / 重降**；
  「还原」= 去掉升降号写回自然音级）
- [x] 调号 `1=C` 显示于谱首（页眉信息带左栏），并参与 MIDI 导出与播放的绝对音高换算

### 7.2 时值
- [x] 全/二/四/八/十六/三十二分音符
- [x] 附点（**只有单附点**：模型是 `dotted: boolean`；满两拍时附点半拍改由增时线表达）
- [x] 增时线 `-` 水平居中于数字中线，落在拍份网格上
- [x] 减时线下划线，相邻同类连成连续线（beam）
- [x] 小节内按**拍份列宽**分配水平宽度（全曲共用同一套列宽，节拍网格处处对齐）

### 7.3 小节与结构
- [x] 单小节线、终止双线、反复 `|: :|`（小节线只覆盖音符区，不穿歌词带）
- [x] 自动换行（每行尽可能多的小节，`barsPerLine` 可固定）；列宽只放大不缩小
- [x] 标题/副标题/演唱/词曲作者/调号/拍号/速度 头部排版（画进 SVG，四处导出一致）
- [x] 歌词逐音节居中对齐音符，**同一行所有音节对到一条基线**（连字符是歌词自带的，排版不添加）

### 7.4 当前实现要点（v0.1，随代码同步）

**排版模型**：全曲共用一套「拍份列宽」——小节按拍号切成等数拍份列（4/4 = 4 列），
所有小节共用同一套列宽 → 节拍网格在**整页每一行**处处对齐；小节宽度 = 行宽 / 每行小节数，
每行小节数 = 可用宽度 / 小节自然宽度（即每行尽可能多的小节）。

- **小节内按时值比例分配宽度**：拍份列宽按落在该列的记号自然宽度等比放大（`grow = max(记号自然宽 / 跨越列数)`），
  记号内不溢出；稀疏小节不被整小节撑宽（无记号触及的列下限为 0）
- **记号左对齐拍份**：记号盒左边缘贴所在拍份左边缘，同一拍份上的记号在任意行、任意小节 x 相同
- **休止符自然宽度** = 一个数字宽（全休止符 4 拍宽、二分休止符 2 拍宽）
- **二分 / 全休止符按四分休止符拆分渲染**：`restSlots` 给出每个「0」的 x（= 所在拍份左边缘 + 半个数字宽），
  故 `0 0` / `0 0 0 0` 与同小节四分休止符、四分音符落在同一记号位置；附点休止符不拆分（单个 `0` + 附点）
- **满两拍的音符写作「数字 + 延长线」**（`dashCount`）：每根横线至少占一个拍份单位（`DASH_UNIT_W`），
  紧凑网格下渲染层的横线区不会塌陷成一小段
- **延长线取该拍的记号位置**（`dashSlots`）：补出的每根横线落在其后各拍的拍份网格上
  （= 拍份左边缘 + 半个数字宽），显式延长线记号同此位置 → 横线与上下小节同拍的音符竖向对齐，
  而不是居中摊在拍份里（居中会比同拍记号右移半个拍份）；横线长度固定为 `DASH_W - 4`，不随拍份宽度拉伸
- **附点规则**：满两拍时附点的那半拍由延长线表达 → 不写附点（附点二分 = `5 - -`、附点全音 = `5 - - - -`）；
  不足两拍才写附点（附点四分 = `3.`）
- **歌词音节宽度计入记号自然宽度**：紧凑网格下相邻音节不会互相重叠
- **窄容器**（容器宽 < 全曲自然宽度）：内部不压缩，按需出横向滚动条，网格仍按自然宽度对齐
- **每行小节数**：`barsPerLine = 0` 自动；`> 0` 固定每行小节数（设置面板可配）
- **小节号**（`showBarNumbers`，默认开）：灰色 `n.` 标在每个记号组左上方，随换行重算
- **圆滑线**（slur）：记号级布尔 `slur`（true = 与前一个音符之间起弧线）；连续标记的三个以上音符
  共用一条弧线，跨行时按行分段续接；组内任意音符的八度点都抬高整条弧线，避免弧线穿过高音点
- **连音线**（tie，同音相连）：记号级布尔 `tie`（true = 与前一个**同音高**音符连成一条时值），
  渲染为弧线，播放时只发一次（时值累加进链首）；`Alt+T` /「简⌒」把小节内同音连音线链合并成更长时值
- **三连音**：记号级布尔 `triplet`，渲染为数字上方的 `3`（`TRIPLET_UP` 高度，行高会为它让位）

**渲染**：SVG（`viewBox` 随排版结果，等宽字体保证文本测量确定性）；
**播放**：Web Audio 前瞻调度 + 逐音高亮；**导出**：JSON / MIDI / SVG / PNG / 文本简谱（打印走浏览器）。

## 8. 文本简谱格式（侧栏「简谱文本」框，`core/jianpu-text.ts`）

```
1 1 5 5 | 6 6 5 - | 4 4 3 3 | 2 2 1 -
1./ 1./ 2 3 | 4 4 3 - |
|: 2 3 5 6 | 5 - - 0 | 3 5 6 1' | 2 - - - :|
```

- 高八度用 `'`（`1'`，可叠加 `1''`），低八度用 `,`（`1,` / `1,,`）；`#` / `b` 是数字**前缀**。
- 时值：数字后跟 `/`（八分）、`//`（十六分）、`///`（三十二分）；`-` 增时线每根延长一拍；`.` 附点。
- 休止：`0` 四分，`00` 二分，`0000` 全休止。
- 小节用 `|` 分隔，反复用 `|:` `:|`；整段不写 `|` 时按当前拍号自动切分小节。
- 该文本可被 `parseJianpuText` 解析回小节（round-trip 一致），见 `tests/jianpu-text.test.ts`。
- 乐曲信息（调 / 拍号 / 速度 / 标题 / 词曲作者）**不在文本内**，由侧栏「乐曲信息」维护；
  三连音、圆滑线、歌词同样不在文本格式内。

## 9. 导出实现要点

- **JSON**：`io/json.ts` 的 `serializeScore` / `deserializeScore`，含 `version` 字段便于迁移；
  导入逐字段校验并吸附（字号走 `snapFontSize`，认不出的调名静默退回 C）；下载与 localStorage
  自动保存共用这一份。
- **MIDI(.mid)**：SMF format 1，单轨；写 `MThd`(ppq=480) + `MTrk`：
  `tempo` meta(0x51) 设 ♩；`timeSignature`(0x58)；`keySignature`(0x59，由 `keySignatureSharps` 换算)；
  逐事件 `note-on/note-off`(delta tick)；休止 = 静音推进 tick；附点乘 1.5；
  歌词按起始 tick 写回 meta `0x05`（round-trip 不丢词）。
- **SVG**：`core/render.ts` 的 `scoreToSvgString`（内嵌样式、无外链），页眉一并包含。
- **PNG**：SVG 序列化 → `Image` → `canvas` → `toBlob` → 下载；尺寸乘上 `LayoutResult.scale`
  （字号缩放），`viewBox` 保持标准单位。
- **文本**：§8 格式（`core/jianpu-text.ts`）。
- **打印**：浏览器打印，`@media print` 在 `src/styles.css`。
- **MusicXML**：**未实现**——与打谱软件交换走 MIDI，工程文件用 JSON。

## 11. 关键风险与对策

- **beam 连续线跨小节**：按小节分组，小节末断开（符合规范）。
- **歌词多音节对齐**：音节居中落在数字中心下方，**同一行所有音节对到一条基线**；
  记号盒宽度计入整音节宽度，相邻音节不压字；字号由排版层写进 `font-size` **属性**
  （CSS 里写 px 字号会压过呈现属性，既不随谱面字号缩放，也与排版基线错位）。
- **首调音准**：所有绝对音高由 `tonicMidiBase(tonic, 4)` 换算（调主恒落在 **C4–B4** 窗口），
  避免写死 C 调。`Tonic` 没有八度字段，所以导入 / 播放 / MIDI 导出 / 移调 notes 模式
  **必须用同一个基准**，否则谱面自洽而发声整首差一个八度。
- **MIDI 时值取整**：ppq=480 时最细的三十二分 = 60 tick，整除无误差；附点乘 1.5
  （模型只有 `dotted: boolean`，不支持双附点）。
- **SVG→PNG 字体**：导出 SVG 内嵌一份样式，字体栈只用系统等宽字体、无外链，
  避免 canvas 跨域污染。
- **性能**：目前每次改动整页重排 + 重建 SVG（无虚拟滚动、无增量重排）；
  长谱面下编辑有可感知延迟，是已知取舍（`meta.barsPerLine` / 字号可缓解）。
- **播放防爆音**：主输出串软限幅、停音一律淡出、前瞻批量建声部（详见 §6.2）。
